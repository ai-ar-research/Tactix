# AM476: current-source D2F checker-state boundary

This is a diagnostic of the published Opus AM465 D2F handoff, not a proof repair or N2 acceptance. Source HEAD was `d464f5f6`; `src/proof/proof.cpp` is unchanged since the AM472 batch repair `ab879129`. The published AM465 `pfx.cpp` driver was rebuilt against that exact current serializer (`pfx-current` SHA-256 `7100f6ce...`), and the pinned no-option `dsr-trim` SHA-256 remained `3b5c7737...`. All solver/checker executions below used SLURM; scripts and result files are under `benchmarks/probes/scratch/am476-d2f/`.

Job `1729601` replayed the two classified, bounded internal Proof API programs from `benchmarks/runs/20260926-am465-split-unit-claude-fuzz/handoffs/D2F-internal-api-checker-retained-deletions/`. Their current-source proof bytes are **identical** to the archived old-source proofs. Input-root-reason seed `4651064600` rejects both backward and forward no-option DSR: forward reports no UP contradiction at the first witnessed addition, and backward reports a missing watch pointer. Deleted-unit seed `4651234831` rejects forward because the checker retains deleted unit `-5`; backward `dsr-trim` elaborates but pinned Trestle reports `s INVALID` (job `1729708`). Thus neither has a complete canonical DSR→LSR→Trestle certificate on the current serializer.

The production kernel normally materializes a root unit before retiring its reason (`kernel_materialize_dsr_root_unit`, then `Proof::del`). To test that exact mechanism on the first internal script, job `1729623` inserted the corresponding `N 1000 -4` event immediately before the deletion. The emitted proof uses the general split transaction: `(-12∨54)`, `(-12∨¬54)`, delete `(36∨-12)`, publish `-12`, retire both helpers. Both no-option checker directions **still reject** the later witnessed addition. Input `(-36)` already makes `(36∨-12)` a root-UP reason before any proof event, so moving the deletion ahead of newly published units cannot make the no-option checker remove that input reason. This bounds the existing batch repair; it does not prove that every alternative DSR certificate fails.

Production reachability must be assessed separately. The D2F scripts call `Proof` directly and can delete a clause without applying a public rule. A current-binary public C-API control on the same CNF (job `1729650`, xdrv SHA-256 `6400b226...`) requested Probe, BCE, explicit X7 clause `12` with empty witness, then solve. Probe made progress, **BCE declined**, and X7 reached UNSAT; the resulting complete 20-byte proof verified in both no-option `dsr-trim` directions and in pinned Trestle (job `1729665`). This control does not reproduce the internal deletion path and neither clears nor establishes a public D2F failure. The ongoing AM473 Opus campaign owns broader current-proof-source public-policy reach and its bounded handoff.

Source inspection identifies the general risk without classifying all executions: `dsr-trim` defaults to ignoring deletions of unit clauses and clauses serving as root-UP reasons (`dsr-trim.c:1474-1490,3562-3584`), while the serializer's `Proof::del` assumes a deletion changes checker population. Kernel deletion materializes root units, but it cannot move an input-root reason before the input itself. Proof-only transient unit deletions in BVE, Sweep and Congruence are additional potential intersections; their actual public reach and certificate validity require targeted oracle evidence. The established AM404/407 option experiments show that `--delete-implied-units` is non-monotonic across real solver proofs, so this report changes no checker option, route, public X7 guard, or source code. The next decision requires AM473's bounded public result plus a general proof-state or certificate-construction design; case-specific reorderings are not acceptance.
