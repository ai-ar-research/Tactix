# AM533: no-MAB online-learning readiness code audit

This is a code-surface audit for the eventual Andrew handoff, not a request to start learning before the no-MAB milestone or a claim that N1--N4 pass. Source is the restored no-MAB `d170b4a5` implementation, byte-identical in current `src/` and `tests/`.

**Inprocessing dose and order are represented.** The public online program (`include/tactix.h`, `tactix_online_step` and v2/v3 additions) carries an ordered step sequence, rule ID, typed parameters, instance payloads, repeat mode/limit, work unit, per-rule and invocation budgets, filters, and post-application action. `src/strategy/online_inprocess.cpp` validates and executes this program with consumed-work accounting; the no-MAB pinned full Debug run has already passed `online_inprocess` and `online_all_actions`. `DefaultStrategyConfig::Inprocess` separately exposes ordered stage lists, effort fractions and repetitions for the shipped policy. These are useful action surfaces for a future learner, but no measured reward attribution or learned arm selection is claimed here.

**Branching and deletion have pre-solve injection seams, not live learner arms.** `src/policies/subpolicy.hpp` defines named `BranchingPolicy::pick` and `ReductionPolicy::victims` interfaces. `DefaultPolicy` borrows optional branch/reduction pointers and otherwise uses `DefaultBranching` and `GlueTieredReduction` (`default_policy.hpp/.cpp`). The source explicitly says live switching is unimplemented: borrowed ownership, safe switch boundaries, and state migration lack a policy-layer contract. The current no-MAB brancher uses VMTF in focused search and EVSIDS in stable search, selected through SwitchMode; there is no MAB/CHB arm. `ReduceParameters` exposes tier protection and a victim fraction, and `reduce_apply_refs` separates deletion effect from policy selection, but `ReductionPolicy::victims` chooses only a prefix length after candidates have been ranked by the existing policy. A learner that changes clause-retention ranking or switches reduction strategies during a solve still needs an explicit state/safety contract.

**Verdict.** The code supports configurable inprocessing schedules and pre-solve branch/deletion substitutions, but is **not ready for online learning** that switches all three strategy families during a solve. First complete the no-MAB correctness/performance milestone and Tier D comparison; a next session can specify arm ownership, switch points, state migration, reward/attribution, fallback and proof/model regression gates. This finding does not require reinstating MAB. The final Andrew-facing readiness report should cite the milestone's terminal evidence and this code audit, and may retain a "not ready" verdict without learning implementation.
