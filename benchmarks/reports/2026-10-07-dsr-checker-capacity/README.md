# DSR checker capacity audit and supported long build

The exact pinned checker uses 4-byte `srid_t` capacities. Upstream `RESIZE(x) = ((x * 3) >> 1)` overflows signed `int` at x=715,827,883. Slurm UBSan reproduces this without a large allocation. An explicitly wrap-enabled diagnostic computes capacity -1,073,741,824 and a request of 18,446,744,069,414,584,320 bytes. This illustrates the mechanism; the original expression has undefined behavior. LONGTYPE correctly computes capacity 1,073,741,824 and 4,294,967,296 bytes.

Default checker SHA256: `3b5c773706dc4695f08115ce862e991bfa2e44e3388df80f40ae8b0823dfbdee`. `nm -S` proves 4-byte literal-database and formula capacities; the clean supported `make long` build proves 8-byte capacities. Long dsr-trim SHA256: `94f5fc0c122b7996207fb38f9010180f2d1e6b61b3008a3ef515ab5d971bc614`. Long compress SHA256: `3adb3fd6f98ff743550eea0a7f7096b2dcc8ef0637e9dec382c582b553e64ff9`.

Source: upstream `0b8cc0ef4d228c059994923cbc66abeb9a42ea14` plus maintained forward-elaboration patch SHA256 `edd70e504e573fbf9801a1c9f80a05fae04e2bcadd763a1e2a1b2b923df3afc6`. Every source/header was checked against its upstream object or one of the two authenticated patched-source hashes. The mutable root clone has extra changes and was not used. GCC 13.1.0 built the archive with `make clean` then `make -j2 long`. Switching flags over existing objects is unsafe because Make does not track CFLAGS changes.

Final Slurm job **1754053** passed **33 directed controls**: 16 valid RUP/witnessed proofs spanning 32/64-bit, ASCII/binary, backward/forward modes, each independently verified by Trestle; 16 invalid empty/witness proofs failed closed; and Trestle rejected an invalid LSR. Existing error/rejected classifications were preserved. Earlier fixtures exposed an upstream one-clause hash-table initialization error and a semantic-error classification; neither was accepted. These controls qualify a diagnostic pin, not arbitrary large proofs.

The overflow is consistent with Rank1004's xrealloc failure at 4.52 GB RSS despite a 32 GB allocation. Causality still requires the same certificate. The old 5,173,305,128-byte certificate was deleted. Target campaign `benchmarks/runs/20261007-rank1004-checker-width-compare` regenerates it using the immutable 0e6b95c91 solver/options, retains it, and compares elaborators followed by independent Trestle. Limits: solver 5000s, each checker pipeline 14400s, 32 GiB Slurm cgroup. This historical checkpoint includes retired noL; any recovery establishes checker evidence, not final-candidate qualification.

Production checkers, acceptance rules, and solver code remain unchanged. LONGTYPE doubles ID/capacity arrays, so memory still needs measurement. Integer variable/literal ranges and other int-typed RESIZE users remain bounded. No instance is counted closed here.
