# AM385: learning-readiness review with native-DSR proof gate

Date: 2026-09-25. This is a source and checker-evidence review, not a solver repair or a gate acceptance. The prior architecture review is [AM376](2026-09-24-am376-online-learning-readiness.md); the new bounded correctness witness is [AM369 H2](../runs/20260924-am369-condition-explicit-claude-fuzz/handoffs/H2-preexisting-dsr-sr-watch-pointer.md).

## Verdict

Tactix can prototype opt-in, explicit root-boundary pass order and dose today. It is **not ready for production online learning** that changes the mature DefaultPolicy schedule or live branching/clause-deletion strategies. The two major *learning-enablement* refactors remain policy-layer work, not a kernel or proof-rule rewrite. Independently, the AM369 H2 native-DSR rejection is an open **N2 correctness gate**; no learning readiness or full Tier-D promotion is implied while it remains open.

## Evidence for the two requested controls

1. `src/strategy/online_inprocess.hpp` has ordered `OnlineInvocation` steps with work/application budgets, repeat modes, typed payloads, and `ReconfigureMode::RetainMatchingStepBudgets`. `OnlineStrategyExecutor::advance` is atomic and detects stale selections. `include/tactix.h` exposes `tactix_online_configure_v3` and `tactix_online_advance`; `tests/test_online_inprocess.cpp` tests retained budgets, interruption and reconfiguration. This is enough to prototype an *explicit alternative schedule*. `DefaultInprocessScheduler::SlotEntry` and `SlotClock` in `src/policies/default_inprocess.hpp` still separately own admission, metering, delays, cursors, follow-ups and telemetry. A learner cannot adjust the same mature default schedule in place without first extracting a shared policy-layer slot controller/adapter and proving default action/work/proof replay and runtime preservation.
2. `src/policies/subpolicy.hpp` defines branching, candidate-order, reduction-count, BVE-bound and Factor interfaces. `DefaultPolicy` and `DefaultInprocessScheduler` inject some as borrowed raw pointers. `DefaultPolicy::solve` is synchronous; the public C API has no mid-solve sub-strategy switch request. The Reduce path in `src/policies/default_policy.cpp` calls `reduce_candidates` and tiers before `ReductionPolicy::victims`, so that interface switches only victim *count*, not a complete deletion strategy. Restart/mode/rephase clocks and the inprocessing slots are not yet swappable sub-policies. An owned, typed handle, deterministic switch boundary, and explicit preserve/reset/migrate rules are needed. Begin with default-exact branching and full reduction adapters; add the remaining search clocks incrementally. Keep default behavior and low overhead as gates, not assumptions.

## New proof gate and rejected checker shortcut

AM369 H2 has a 21-variable, 42-clause original-CNF reproducer. The candidate and parent `b2dc0fd9` emit byte-identical native DSR, and pinned no-option `dsr-trim` rejects at the first proof-only SR extension. Verbose checking reports six original clauses whose deletion is ignored because they serve as implied-unit reasons after the first explicit unit. This leaves checker-visible clauses absent from the solver's later SR-validation formula. The checker option `--delete-implied-units` makes the H2 certificate verify through `dsr-trim` and independent Trestle (including forward elaboration), but it also changes the historical no-option Satsuma+Kissat acceptance route recorded in `docs/calculus.md`, `docs/implementation-notes.md` and the maintained oracle. The existing `tests/micro_proofs.sh` negative control then becomes accepted. The option was therefore **not** adopted; the experiment was rolled back, leaving the worktree's oracle contract unchanged. The control's acceptance may reflect changed deletion semantics rather than unsoundness; it cannot justify a silent checker-route change. A general solver/proof-state repair or an explicitly approved contract change with new positive and negative controls is still required.

This H2 defect is not caused by the learning interfaces. It nevertheless bars the N2 prerequisite for learning and the user-authorized full Tier-D run. Fixed proof-oracle tests and the harness self-test passed during the option experiment, but the native `micro_proofs` suite failed the negative control; none of those results is a repaired-candidate acceptance. No solver behavior, rule semantics, or benchmark result changed in this audit.

## Sequencing

Close H2 and the pending Claude-owned proof/model fuzz and matched N1--N4 gates first. Then extract the shared slot controller, establish an exact DefaultPolicy replay arm, and add owned event-boundary branching/reduction switches with state-lifecycle and proof/model tests. Measure the plan's at-most-5% default-vs-hardcoded overhead and §8.5 L-safe/decision-cost gates before trusting online rewards. The 5,000-second full Tier-D comparison stays downstream of the existing goal gates.
