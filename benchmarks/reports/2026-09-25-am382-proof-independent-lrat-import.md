# AM382: proof-independent eager import for native LRAT

Date: 2026-09-25 UTC. Parent: `a1dba2cf`. This is a focused N2/import-invariant repair checkpoint, not combined N1/N2 acceptance or a performance promotion.

## Cause and general repair

AM372's Opus owner observed proof-on/proof-off X5 liveness differences. A fixed four-line import shape isolates one cause: `(-1 ∨ 2)`, then unit `(1)`, then `(2 ∨ 3)`. Proofless, DRAT and DSR ingestion propagates the unit immediately, forces `2`, and omits the already-satisfied third clause. Native LRAT previously deferred that propagation until all raw input IDs were reserved, so it retained `(2 ∨ 3)`. The new `test_parse` assertion failed only for LRAT on the parent, after root closure, with the third binary still live. This contradicts the proof-independence invariant in `docs/calculus.md`; it does not imply that the owner's accepted certificates were invalid.

The live DIMACS parser now always performs eager clause admission and root closure even when native LRAT was selected. It temporarily detaches that serializer, preserves exact raw input and binary IDs, then replays all original clauses in a temporary proof kernel at the completed input boundary. The replay uses the pre-existing C-API late-attachment transaction, now shared in `frontend/parse.cpp`: it derives post-input LRAT units and restates the live normalized clauses with fresh checker IDs, maps only proof identities back, and leaves live assignments, watches, reasons and guidance untouched. C-API early LRAT selection uses the same deferred route; late attachment retains its existing behavior. Other early proof formats remain direct. The temporary raw-input copy and binary-ID archive are explicit-LRAT costs; their large-input memory and time impact is not yet measured.

The parser path automatically defers any directly attached LRAT proof, not just the competition CLI, so another caller cannot accidentally take the old divergent path. Error exits restore the original proof pointer without emitting a partial derivation. This changes no proof rule's abstract guard, effect or proof delta, and does not add a default scheduling arm.
