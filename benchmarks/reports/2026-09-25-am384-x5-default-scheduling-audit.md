# AM384: X5 Condition default-scheduling source audit

Date: 2026-09-25 UTC. Scope: pinned-reference source and current-policy audit, not a new solver run or combined N4 acceptance. The reference is local CaDiCaL `rel-3.0.0` (`7b99c07`); the current Tactix source is `332d2be4` before this documentation checkpoint.

## Finding and disposition

CaDiCaL's shipped `condition` option is **0** (`cadical/src/options.hpp:58`), so its ordinary default cannot enter `Internal::conditioning`: that function first returns when `!opts.condition` (`condition.cpp:35-38`). The search loop's `conditioning()` → `condition()` branch (`internal.cpp:328-329`) and the opt-in initial call (`internal.cpp:719-720`) are therefore inactive by default. Tactix likewise omits Condition from `reference_inprocess_program()`, excludes it from the unlisted-rule append path (`src/policies/default_policy.cpp:3311-3316`), and leaves canonical `condition_apply(Kernel&)` as NoOp. `test_scheduling` asserts the deliberate absence, while `check-effort-specs.py` independently checks the omission, NoOp, typed API and fixed API-driver evidence. Thus **the shipped default-off decision matches the pinned technique owner**; this closes only the X5 default-admission question, not overall N4 verification.

When explicitly enabled, CaDiCaL has more than a Boolean switch. At a search boundary it requires a conflict interval, at least one decision, decision level above the moving average backjump level, nonempty irredundant formula and a bounded clause/active-variable ratio (`condition.cpp:35-62`). Its call budget scales search propagations by `conditioneffort=100` per mille, clamps between `conditionmineff=0` and `conditionmaxeff=1e7`, and scales by active variables / irredundant clauses (`condition.cpp:895-920`); the next conflict interval grows with the conditioning count (`condition.cpp:930-936`). The producer extends the current search assignment, rotates previously tried candidate clauses, refines conditional/autarky literals under a propagation limit, and saves a variable-length cube for reconstruction (`condition.cpp:155-230, 442-505, 750-793`). Tactix does **not** implement that automatic producer or its opt-in schedule; it implements the complete typed explicit `(C,W)` action. The missing optional producer matters for a future learnable Condition strategy, but is not evidence that Tactix's current default schedule is weaker than the owner's shipped default.
