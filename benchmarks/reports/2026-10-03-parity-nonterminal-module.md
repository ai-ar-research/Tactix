# Reusable nonterminal parity proof module

## Implementation

`src/rules/lucky/parity_certificate.hpp` now owns the bounded-clause XOR encoding, local RUP derivation engine and balanced extension-variable residue tree previously private to `parity_refutation.cpp`. The native refutation keeps its existing collector, proof sink and `run` contract: success means a contradiction was emitted. The extracted engine adds a single-use `accumulate` operation and `export_small_consequence` for a caller-selected support bound up to four original variables. The export emits every clause of the accumulated XOR relation; it does not install kernel clauses or create live search variables.

Every fresh tree variable is defined by pivot-first RAT clauses. Local RUP chains relate old/new tree nodes during equation accumulation. A root unit fixes the final parity. The export gathers active tree definitions and that unit, then derives the small relation over original variables by the same local proof engine. An empty consistent residue exports nothing; a terminal contradiction is reported separately. Malformed equation variables are rejected before proof emission, and incomplete accumulation cannot be exported. Width limits are checked before export emission. The caller-owned sink controls proof addition limits and cancellation; interruption during export may retain a valid partial prefix. No rollback or live action fallback is introduced.

The helper does not certify a heuristic equation recognizer. Its inputs still require complete clause-backed premises, current mappings and appropriate root conditions. Sink ownership includes fresh-ID allocation, action/proof provenance and retirement. The previous terminal sink's proof-only variables must not be installed as live branchable variables without an explicit allocator/mapping contract. Public typed action integration, policy admission/intervals, duplicate suppression, raw feedback and lifecycle publication remain pending.

## Validation

The [retained run](../runs/20261003-parity-nonterminal-module/) contains sources, checker commands/results, hashes and original CNF/proof artifacts. Native `test_parity_model` and `test_startup_parity` pass against the extracted module, linked with hash-verified immutable parent objects and a newly built parity object. The final focused pin is `build/pin-parity-nonterminal-c6dd5f8f-02`; the earlier pin records the first compile before an explicit standard include and additional standalone tests. These are focused controls, not full Debug or regression acceptance.

The new fixed test covers equality/inequality export, units, three- and four-variable equations, consistent empty residue, contradiction, invalid mapping, single-use behavior, insufficient width and addition exhaustion. The four-equation cancellation fixture emits 250 prefix additions using 14 fresh proof variables. The complete 6,310-byte witness-free DSR audit includes a disjoint unit-free closing gadget, as in earlier controls. Canonical DRAT/CakeLPR checking and forward every-addition DRAT checking pass. A deletion-aware LRAT elaboration independently verifies every addition with CakeLPR; the elaborator asserts that nonterminal prefix hints never cite closing-gadget premise IDs. A deliberately unsupported unit fails CakeLPR. The independent checker is the oracle, not the elaborator.

This small fixture's extension proof is larger than the earlier 30-addition direct resolution proof. No compactness or performance advantage is claimed on this fixture; the value is reusing a bounded-local-derivation engine without requiring terminal contradiction. Selection should retain direct clausal derivations when they are cheaper. Larger-support scalability and practical payoff require separate evidence.
