## Why the ncc route cannot simply be switched on

For the exact original CNF `p cnf 1 2; 1 1 0; -1 0`, the one-line witness-free ASCII DSR empty claim is verified by pinned `dsr-trim`, which emits LSR `2 d 0; 3 0 1 2 0`. Pinned CakeLPR **rejects** this raw LSR against the original duplicate-literal clause (`Checking failed at line: 1`), even though its process exits zero. Thus AM378's ncc success is not a universal route contract by itself; duplicate-input normalization must be reconciled with the exact original CNF.

The maintained `canonical_checker_cnf` + `restate_duplicate_input_lrat` helper already performs the needed proof-only restatement while leaving the original CNF intact. Applied to this `dsr-trim` LSR, it produces a one-clause RUP restatement, retires the original ID, shifts derived IDs and rewrites hints. CakeLPR then prints exact `s VERIFIED UNSAT`. The same sequence succeeds for **binary DSR → binary LSR → decoded LSR → restatement → CakeLPR**. The ASCII and binary-derived restated LSR files are byte-identical (SHA-256 `9c9b5ce9ffe5537f21d78897684bb968f213b53282a35fd0957827d40b509dd9`). This tests compatibility of the existing LRAT restatement helper with this LSR shape, not every LSR grammar form.

An original CNF with an input empty clause makes pinned `dsr-trim` emit hintless `2 0 0`; CakeLPR rejects it. The maintained `bridge_trivial_input_lsr` changes only that exact trivial output to cite the original empty clause, after which CakeLPR verifies. A satisfiable two-clause CNF plus the same false DSR empty claim is rejected by `dsr-trim` (exit 1, unable to derive the empty clause). A corrupted restated LSR is rejected by CakeLPR (`Checking failed at line: 3`) **despite exit 0**. Exact status text, not exit code alone, is mandatory.

It is not broad evidence for all witnessed/witness-free formats, malformed readers, proof sizes, timeouts, or resource limits.
