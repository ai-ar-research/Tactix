# AM380: public Decide-candidate enumeration closes the input boundary

Date: 2026-09-24. This is a focused N1/N2 API-lifecycle repair checkpoint, not combined N1/N2 acceptance or a Tier D run.

The public contract in `include/tactix.h` requires proof attachment before the first operation that reasons about the input, including enumeration. `tactix_rule_instances` and `tactix_rules_applicable` call `input_complete`, but `tactix_decide_candidates` did not. A caller could enumerate branching candidates and then attach a proof, reopening the original-input proof-ID boundary after observing an input-derived snapshot. The fixed regression in `tests/test_api_c.c` adds `(1 2)`, enumerates two candidates, and requires a subsequent DSR proof attachment to return `-1`. On the parent implementation it fails at that assertion: attachment returns success. The repair calls the same idempotent `input_complete` before positive-capacity candidate enumeration; zero-capacity calls remain non-reasoning no-ops. No rule guard, branch choice, default schedule, proof serializer, or calculus rule changes.

Focused Debug, Release and ASan+UBSan builds each pass `api_n1`, `api_instances` and `proof` (3/3 per mode). The Debug old-code control failed the new assertion before the one-line repair. These tests establish the boundary behavior; they do not exhaust all public API interleavings or independently certify a new proof route. A frozen-source Claude Code Opus affected-scope fuzz owner is required before this checkpoint can count toward N1/N2. Existing AM351/363/369/372/373/376/377 owners and retained performance gates remain independent and open. No Tier D task was submitted.
