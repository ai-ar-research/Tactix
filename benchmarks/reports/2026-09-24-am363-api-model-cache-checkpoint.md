Date: 2026-09-24. Base source `8a79afbf`; this is an affected-scope N2 repair checkpoint, not a combined N1--N4 or performance-gate acceptance. No Tier D run was submitted.

## Bounded failure and cause

The terminal AM360 Opus report records 245,212 Lucky SAT returns with correct immediate status and original-CNF models, but classifies the campaign **FAIL** because of one older model failure M1 (`benchmarks/runs/20260924-am360-lucky-status-claude-fuzz/REPORT.md`). Its minimized 24-variable, 36-clause public-API input (`triage/m1/reproducer/min.cnf`, SHA-256 `d996b73066aa5b659383a5eb817379a0b391b1e521a84e4849660e7cbf026953`) makes CCE progress; Lucky semantic instance 5 returns SAT with a valid original-CNF model. After `tactix_solve`, the handoff driver calls `tactix_solve` again; its final model falsifies original clause `(4 ∨ 3)`. Both the AM360 candidate and its pre-fix controls reproduce the failure. The owner observed 2/100,000 Release cases.

A simpler public sequence on the same CNF isolates the defect without Lucky: `CCE; solve; read all original clauses; solve; read all original clauses`. The **first** solve returns a valid model; the **second** returns SAT with clause `(4 ∨ 3)` false. The new `tests/test_api_c.c` regression failed at pass 1, clause 5 against the old Debug objects and passes with the repair. The corresponding direct-Kernel `tests/test_cce.cpp` path, which extends the model only at its final observation, passes both before and after. Diagnostic proof/model outputs from the old public binary are retained under `benchmarks/probes/scratch/am363-m1/`. Thus the defect is not established as an unsound CCE witness: it is the C API's model materialization across a resumable solve boundary.

`tactix_solve` previously called `prepare_external_model(..., materialize=true)`. `kernel_extend_model` correctly replays reconstruction into `model_values`, but the optional materialization then copied repaired external values into `kernel.values` for still-live variables. That changed the live assignment without changing trail entries, reasons, decision levels, or propagation state. The next `default_solve` therefore read a state whose values no longer matched its search provenance. The fix makes the C API's `prepare_external_model` always call `kernel_extend_model(..., materialize_internal=false)`. It caches the reconstructed original-CNF model for `tactix_value` while leaving live kernel state intact. CLI terminal reconstruction and the underlying witness rules are unchanged. This applies to every reconstructed SAT model through the public API, not a CCE/Lucky or input-shape dispatch.
