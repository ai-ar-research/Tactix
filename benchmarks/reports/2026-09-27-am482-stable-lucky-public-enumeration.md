# AM482: stable Lucky public instance enumeration across proof modes

Opus AM473's terminal public-program twin handoff showed eight DSR/AUTO-versus-proofless UNKNOWN divergences that first differed at Lucky's public instance count: 19 with an explicit DSR writer, 21 without proof. There was no SAT/UNSAT contradiction. Source diagnosis is general: `main.cpp` and the C API close `startup_certificate_open` for strict clausal writers, and `Lucky::instances` previously omitted startup-PBP IDs 19 and 20 when that flag was closed. A random or replay policy could therefore select a different logical action merely because proof output was attached. The plan requires stable logical action selection; explicit DSR/DRAT/LRAT still cannot emit startup PBP.

The registered Lucky enumerator now returns stable IDs 0–20 at every public Lucky boundary, regardless of writer or startup state. `apply_instance` retains the existing certificate and boundary checks: IDs 19/20 decline as byte-invisible `NoOp` when unavailable. This changes no solver formula, default-policy dose, proof serializer, checker routing, or X7 legality. A focused public C-API regression compares proofless and strict-DSR lists, tests capped enumeration, applies both unsupported startup IDs, and checks that the strict stream remains empty. The pre-change source returned 19 for that strict-writer case.

Release and Debug focused `api_instances`, `startup_parity`, `count_preservation` and `random_online` tests pass. Release and Debug `startup_parity_check` independently verify all six API PBPs and the default/normalized original-CNF PBP with VeriPB then CakePB. `count_preservation_check` independently verifies four API/default original-CNF PBPs and a raw-normalization proof, with its missing-derivation negative control rejected; no-proof controls agree. The Debug build enables the proof shadow. These are fixed affected-scope checks, not a full current-source fuzz or N1/N2 acceptance. Compiler warnings came from unchanged Vivify/SubSolver code.

AM473's direct Proof API D2F traces remain rejected on the prior/current serializer; this change does not alter them. The public X7 validator checks the kernel's root units and live clauses, whereas those scripts can delete a root reason or proof unit without maintaining the kernel's root state. That difference bounds the handoff but does not prove all production traces safe: BVE, Sweep and Congruence emit and retire transient proof lemmas, and checker-retained units remain a potential intersection. Opus must target public producer reach on the new pin. Full Debug, combined fuzz, automatic-proof Rank/B28+C5, WV100 and WV2-89 gates remain due; Tier D is not submitted.
