# AM369: explicit general X5 Condition checkpoint

Date: 2026-09-24. Parent source `b2dc0fd9`; this report accompanies the X5 implementation commit. This is an **ungated semantic-rule checkpoint**, not combined N1/N2 acceptance or a Tier D submission.

## Change and contract

Tactix now registers X5 `Condition` at append-only action ID 28. The public C function `tactix_apply_condition` accepts any finite `(live clause C, consistent cube W)` in external DIMACS literals. No witness-in-clause, cube-size, formula-shape, rank, or benchmark restriction exists. It validates the complete tuple before entering the rule-dispatch proof boundary. Root-false candidate literals are allowed; root-true candidates, contrary root witness values, malformed tuples, stale/retired identities, pending conflicts, and interrupted validations decline without an X5 proof or reconstruction event. Binary candidates retire every physical copy; a large candidate retires one exact live clause.

The executable test checks the local implication `¬C ∧ D ⇒ T_W(D)` for every live irredundant large clause and binary copy, under permanent root values. Learned clauses are not locally checked: the calculus invariant `F ⊨ R` makes them true once the overwritten model satisfies the restored irredundant formula. A tagged `(C,W)` segment replays after other reconstruction events and overwrites W only when C is false. The only certificate event is deletion. This implements [CaDiCaL's cube-witness rule](https://github.com/arminbiere/cadical/blob/master/src/condition.cpp) as an explicitly selectable action. DefaultPolicy has no X5 producer and deliberately retains its old program pending N4 scheduling evidence; `tactix_apply` canonical is a no-op, not a hidden heuristic cube choice.
