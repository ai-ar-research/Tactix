# AM358 — root-cube LRAT hint checkpoint (unaccepted)

Date: 2026-09-24. Parent source commit: `63d33996777b9a4d37ef9ee9e6799d1e48e58966`. This is an affected proof-contract repair, not a combined N1/N2 gate or a performance result. No Tier D instance was submitted.

## Cause and general repair

AM349 H2's bounded handoff identifies native LRAT lines whose lemma has a root-false literal. LRAT checks the complete negated lemma cube before processing hints, so the corresponding root unit is **already satisfied**. Congruence's reason walk could nevertheless cite that root unit as if it propagated. Pinned CakeLPR accepts the resulting proof, but the project's strict original-CNF replay rejects it; checker permissiveness does not satisfy our internal hint contract. See `benchmarks/runs/20260924-am349-unary-xor-claude-fuzz/handoffs/H2-lrat-satisfied-root-unit-hint/README.md` for the two exact public-action cases.

`congruence_rup_chain` now records every *named* root unit already true among the complete negated conclusion assumptions and removes its ID from the reason-walk entries before constructing the native-LRAT chain. It leaves the actual conflict-closing clause and all other reasons in trail order. An unnamed root fact cannot be cited and is skipped without a new assertion. This shared replay serves all Congruence lemma families and the legal Hyperbinary/Sweep callers; the change is not tied to either H2 CNF, a literal number, or a benchmark identity. It changes only LRAT hint text, not rule guards, action enumeration, scheduling, SAT state, or DSR/DRAT proof emission. The V6 proof delta and implementation contract were updated in `docs/calculus.md` and `docs/implementation-notes.md`.

The new fixed `test_lrat_replay_omits_root_unit_in_initial_cube` uses original clauses `(-2∨1∨3)`, `(1∨-3)`, and unit `(2)`, then replays lemma `(1∨-2)`. Under its complete negated cube `{-1,2}`, valid hints are exactly clause IDs `[1,2]`; citing unit ID 3 is a satisfied hint. The initial test failed at the root-unit exclusion assertion on the pre-repair source and passes with the repair. This observed negative control was not separately frozen as a build artifact; the corrected owner request requires its own parent control.
