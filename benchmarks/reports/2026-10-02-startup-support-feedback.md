# Startup support completion and operation-map reconciliation

This checkpoint extends common completion around DefaultPolicy's existing
startup representation/guidance mechanics and its post-structured BCE
opportunity. It does not change action selection, scalar reward or the goal's
acceptance bar. The prior frontend/publication checkpoint is `378cd919`;
accepted foundation pins and baseline remain comparison authorities.

## Implemented boundaries

Cold-state materialization and sparse root collection have optional shared
completion overloads next to their existing typed execution in
`representation_execution.hpp`. Disabled materialization performs its original
single call; disabled collection bypasses descriptions/snapshots. Materialization
records whether work was deferred and distinguishes completed from idempotent
NoChange. Collection preserves the exact native NoChange/Changed/Unit/Refuted
return; metadata maps these to NoChange/completed/completed/UNSAT and retains
raw root/formula counters. Neither support transaction adds a proof-rule
application count. Actual native ticks remain a declared currency, including
zero-cost support; no common effort or scalar reward is inferred.

The initial fixed-root compaction of the brancher's random-index permutation
now has a shared typed guidance request and `CompactRandomOrder` completion.
It does not change kernel/public variable identities or claim formula progress.
Cold startup Lucky verdicts still bypass support consumers and H attachment.

The conditional post-structured BCE opportunity uses the same native BCE body,
guard, producer-dependent policy decision and journal candidate. Its completion
retains the effective native parameter profile and actual BCE ticks. The
nested InprocessScope now ends inside the transaction, before delivery (and
before a possible terminal finish), restoring the surrounding startup context
rather than forcing search attribution. No phase or support action replaces
its individual rule record.
