# AM540: four competition-winner Tier D arms launched on cpu-q

At the user's direction, the four pinned reference configurations `kissat-sc2024` (the competition winner), `lymphosat`, `ae-kissat-mab`, and `satsuma-kissat` were submitted as a single full 4 × 1,166 = 4,664-task Tier D array `1733043` on `cpu-q`. The array specification is `0-4663%120`: at most 120 tasks may run simultaneously across all four arms. Each task requests four CPUs and 32 GiB, with a 5,000-second solve timeout and a 14,400-second (four-hour) total proof-check timeout; the SLURM allocation is 05:45:00 including cleanup margin. The AM540 manifest SHA-256 is `c5112af8380a8fd76c2b231960c6a9470ea1f54578e105cfbe855628f7e824d3` in `benchmarks/runs/20260928-am540-four-winner-tierd-cpuq/`. It cites the immutable archived baseline manifest and copies its winner binaries and checker pins; it does not reuse their prior results.

The new run uses the established `portfolio_rerun.py` anonymous solver adapters and `procfd_realpath.c` transport shim. Original and Satsuma-reduced CNFs, solver streams, proofs, models, and checker intermediates are `O_TMPFILE` files under node-local `/tmp`. They have no directory entry and are released by the kernel after normal exit, timeout, SIGKILL, or OOM. The adapters preserve the pinned solver algorithms and convert only their file interface. The model checker checks the original CNF. UNSAT routes remain specific to each winner: Kissat and AE-Kissat-MAB use DRAT→drat-trim→CakeLPR; LymphoSAT uses PBP→VeriPB→CakePB; Satsuma+Kissat uses no-option dsr-trim→dsr-compress→Trestle. The `cpu-q` compute-node validation `1733041` completed 0:0 on `node003`: each of the four arms passed both SAT/model and UNSAT/full proof-chain controls, plus abnormal-exit and timeout cleanup controls. Earlier AM538/AM539 validation bundles failed before submission because the raw winner CLIs cannot all use proc-fd paths directly; their failure records are retained and their superseded pins removed.

Repository allocated usage was 428,522,546,176 bytes before launch, below the 700,000,000,000-byte guard threshold. Guard job `1733242` runs on `cpu-q`; it samples repository usage every 600 seconds, holds only pending tasks of array `1733043` at or above the threshold, and releases its own holds after usage falls below it. The first guard `1733209` was replaced after its 120-second `du` limit proved too short for this NFS repository. The replacement allows 540 seconds for a scan and holds pending tasks if a measurement fails; a focused mock confirms that it never holds a running task and releases its own hold when usage is below the threshold. Successor guard `1733255` is queued afterany `1733242` to cover a possible second seven-day window. It never suspends or cancels running tasks. Its first completed scan at 03:48 UTC measured 428,340,259,840 bytes and held zero tasks. Its state/events are under the AM540 campaign's `storage-guard/` directory. The full no-MAB Tactix Tier D array remains unsubmitted while its milestone checks and the user's timing preference are resolved.

Stale storage removed before launch: AM536's failed preparatory pins (95 MiB); the canceled AM522 MAB fuzz owner's 124 incomplete proof certificates (2,986,474,896 apparent bytes), generated build directory (263 MiB), and duplicate binary pins (178 MiB); and the superseded AM538/539 validation pins. AM522's owner report, freeze, scripts, seed CNFs, repro metadata, and logs remain. Current no-MAB AM531 fuzz and AM519 proof/Debug pins were untouched. The LymphoSAT UNSAT proof rejection on Tier D rank 26 is already present in the archived baseline result for the same formula and checker; the new run records it as invalid rather than relabeling it a solve.
