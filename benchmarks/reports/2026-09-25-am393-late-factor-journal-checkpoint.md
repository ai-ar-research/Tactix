# AM393: late Factor heuristic population and API journal continuity

Date: 2026-09-25. Scope: general repairs for the two pre-existing defects handed off by the terminal [AM373 X5 fuzz report](../runs/20260924-am373-condition-external-claude-fuzz/REPORT.md). This is a local repair checkpoint, not affected-scope fuzz acceptance or a combined N1--N4 gate.

## Result and cause

* A Factor rule can introduce an extension variable before a policy attaches `H`. The later activation seed previously rebuilt `compact_import_order` from input variables alone; the extension remained active but absent from the compact decision/phase population. `heuristics_update_target_phases` could then assert. `heuristics_seed_activation_order` now appends surviving fresh extensions in permanent import order, identified by stable external identity. It does not admit inactive original/header-only identities. `kernel_compact_variables` remaps the pending input activation and compact import images even if `H` is absent, so pre-attachment and detached compactions retain valid dense indices and inverse positions. `tests/test_factor.cpp` covers actual Factor 2-by-3 grid application with early versus late attach, extension plus pre-attach compaction, and compaction after detach before reattach.
* `tactix_solve` used to call `rule_journal_close`, resetting the process-global diagnostic state. A later API transaction reopened `TACTIX_RULE_JOURNAL` in write mode, truncating pre-solve records and restarting sequence numbers. The API now flushes at a solve boundary; one stream spans repeated API sessions. Final close still checks replay exhaustion, registered at process exit for API clients. The new public C driver applies X5 before each of two solves; its Python oracle checks that both `Condition` records survive with sequences 0,1, exact replay succeeds, and a trailing extra replay record is rejected. The default-policy journal fixture now explicitly requests the DRAT compatibility route to exercise search dispatch; native-DSR structured startup can legitimately refute its pigeonhole input before Decide.
