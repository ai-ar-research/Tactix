# AM375: exhaustive small-domain X5 implication oracle

Date: 2026-09-24. Base commit `be85b681`. This checkpoint changes only the fixed X5 unit test; the solver, public API, proof writer, and DefaultPolicy are unchanged. The log, build paths, hashes, and exact command are frozen in `benchmarks/runs/20260924-am375-condition-implication-oracle/manifest.json`.

`test_condition` now compares the implemented X5 `(C,W)` legality result with an independent total-assignment overwrite oracle for 1,080 combinations: binary and ternary candidates, all 20 signed non-unit three-variable second clauses, and all 27 consistent cubes over those variables. The oracle visits all eight total assignments per combination, including witnesses outside `C`, and asks whether every model of `¬C ∧ D` still satisfies `C ∧ D` after the cube overwrite. It does not call or copy the implementation's local-implication calculation. All cases agree in Release, Debug, and ASan+UBSan; the focused current-source Release N1/N2 fixture set passes 21/21.

This strengthens the general X5 legality evidence without selecting a benchmark family, cube size bound, or default scheduling behavior. It is intentionally a small-domain test, not a completeness proof for arbitrary formulas, roots, compaction, proof emission, or all N1/N2 states. Earlier AM372/373 checks cover fixed root and compaction cases with original-CNF proof/model oracles; Claude's separate AM369/372/373 campaigns own affected fuzz. CaDiCaL's opt-in search-time producer remains distinct from Tactix's explicit root-boundary rule, so N4 parity and automatic X5 discovery remain open. No Tier D submission was made.
