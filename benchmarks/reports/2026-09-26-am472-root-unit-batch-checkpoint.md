# AM472: consecutive root-unit proof transaction checkpoint

Date: 2026-09-26. This is a bounded N2 proof-emission repair, not N1–N4 acceptance. The pre-existing D2 handoff from the AM465 Opus campaign is a 31-variable, 33-clause public Probe→BCE→solve program. On `1d81d353` and two older pins, its native DSR proof is rejected in both checker directions, while LRAT and DRAT verify. Six earlier published root units make a BCE-deleted clause a retained checker reason before a later SR witness. The handoff preserves the reduced and original programs; the reduced case is also in `corpus/regressions/dsr-root-batch-d2.*`.

The shared native DSR serializer now stages **consecutive internal `add_rup` units** as one transaction. If a deletion block follows, it publishes two RUP helpers `(u_i ∨ a)` and `(u_i ∨ ¬a)` for every staged unit on one fresh external auxiliary, copies the deletion block, publishes the units in original order, and retires all helpers. Under either auxiliary assignment, earlier pairs supply earlier units to each subsequent helper derivation. After the deletions, each pair makes its unit RUP independently of the deleted reasons. A deletion of any staged unit first publishes the batch; other additions end the batch. Membership indices avoid a linear scan per deletion. With no intervening deletion, direct unit serialization remains in original order. This changes neither public X7 legality nor plan §5 checker routing.
