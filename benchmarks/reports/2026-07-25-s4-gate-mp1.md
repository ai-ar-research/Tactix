## 1. What the gap actually was

Three stacked causes, none of them the missing rule the earlier profile
hunt looked for:

1. **137,700 duplicated input binary pairs** (of 278,580 binaries; all
   2,700 variables touched). kissat's dense mode physically dedups these
   before any inprocessing runs; we stored both copies. The copies
   (a) inflated Factor's watch-score seeds — steering the S2-diagnosed
   "wrong grids" — and (b) **blocked BVE outright**: the duplicate-binary
   hazard (`kernel_delete_binary` refuses copies ≥ 2) NoOp'd every
   candidate variable, so **BVE had never eliminated a single variable on
   mp1 in any configuration** (0 vs kissat's 661; slot-trace probes
   1561167/68 — n=1760 candidates per pass, meter forever 0).
2. **No during-search elimination under the arrangement** — consequence of
   (1), discovered because the arrangement's "deferred BVE" silently never
   arrived (`bve 0 rounds, 0 eliminated` across 13 phases).
3. **No cross-round grid composition** — post-dedup, composite doses are
   the 3× difference (15.5 → 5.34 s, 645k → 178k conflicts): kissat's 855
   factored vars are cumulative chains, not one blast.

Fixes, in commit order: parse-time binary dedup (`beace90` — the
duplicate-unit precedent: id consumed, copy never stored, no proof lines);
BVE duplicate tolerance (`e0e73e7` — dedup gather + all-copies deletion,
the Factor precedent); kissat-exact dosing machinery (`85e43b9`,
`1e50f73` — factor_ticks cache-line currency, uniform work_budget, 700M
first dose + 50‰, factor-LAST, truncated-log factordelay, completion
watermark, persistent completion-gated BVE bound level); density-scoped
composite doses (`c15571f`).
