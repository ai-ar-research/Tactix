\section*{Executive summary}
The 300--580 second Rank-27 spread is execution-environment noise, not solver
nondeterminism, and Kissat exhibits the same effect.  Immutable runs perform
the same logical work and essentially the same instructions, but solvers
sharing one L3 domain consume materially more cycles at lower IPC.  An exact
contemporary Tactix control needs 367.312 seconds at
the isolated median and 419.659 seconds when only one other Rank-27 solver
shares the node.  Instructions change 0.025\%, while cycles rise 14.231\% and
IPC falls 1.805 to 1.580.  Shared cache and memory service rate is the owner;
CPU descheduling, migrations, average frequency, and proofless I/O are not.

The completed node-isolation experiment is causal evidence, not a future
timing or diagnostic policy on a two-node cluster.  Seven isolated proof-off
observations span 365.171--371.637
seconds; three primary repeats have median 367.312 and 1.237\% range.  Three
isolated proof-on observations have median 370.893 and 0.437\% range.  More
importantly for future policy, six ordinary shared-node
\code{-c 12} controls, each reserving one complete L3 domain, reproduce the
accepted Tactix trajectory in 367.045--372.354 internal seconds (median
368.307, full range 1.441\%).  Every run is below 400 seconds.

Proof production itself costs only 3.581 seconds at the isolated median
(0.975\%), not the historical unstable estimate of 28.532 seconds.  Proof
checking is separate: median 112.03 seconds.  All proof jobs reproduce the
current candidate's 1,514,395,111-byte proof and pass pinned \code{drat-trim}.
I/O is not the present solver bottleneck because proofs and inputs reside on
node-local NVMe; the repository is NFS but receives only compact evidence.

The approved policy uses ordinary shared-node \code{-c 12} allocations with
exactly 48,000 MiB of scheduler memory while retaining the 16-GiB solver
process limit, simultaneous separate candidate/baseline jobs, three independent paired waves
for decision-grade performance claims, and median ratio/full-spread reporting.
Fuzzing remains one Claude-owned campaign and is not repeated by this policy.
Future whole-node isolation is prohibited.

\section{Diagnostic calibration and CPU allocation}
Bare \code{--exclusive} is unavailable on this partition.  The supported
combination \code{--exclusive=user --mem=0} provides effective isolation:
exclusive-user ownership excludes other users across partitions, and reserving
all memory prevents another same-user job fitting.  A shell \code{ulimit}
independently retains the actual 16-GiB solver contract.  Node snapshots show
one timing job, node owner \code{hwu}, and all 751 GiB reserved.

The EPYC 9454 nodes have two hardware threads per core.  Ordinary \code{-c 2}
exposes \code{0,96}, one physical core; ordinary \code{-c 4} exposes
\code{0-1,96-97}, two cores.  On this cluster, \code{-c 2} plus
\code{--hint=nomultithread} also exposes the two-core mask.  Isolated ordinary
\code{-c 2} runs are 366.609 and 365.171 seconds; isolated ordinary
\code{-c 4} runs are 368.081 and 367.295.  Their medians differ 0.49\%, which
is immaterial.  Tactix is single-threaded: \code{-c 4} is a clearer ordinary
allocation, not computational parallelism.  It reserves two physical cores
and matches the partition's 16-GiB-per-two-core convention, but does not reserve
shared cache or memory bandwidth.  It is suitable for functional work but not
long-instance timing.  \code{-c 12} is the minimum scheduler-visible allocation
that reserves a complete six-core L3 domain on these nodes.  It retains the
16-GiB process contract and ordinary shared scheduling.

\section{Proof and I/O decomposition}
Proof-on median minus proof-off median is 3.581 seconds, 0.975\%.  Median cycles
rise 0.980\% and instructions 1.336\%.  Every proof has 1,514,395,111 bytes and
SHA-256
\hashcode{7bcb3d8db7fe5827daa6af18281684b1f82f79c4f28468046a88b2ab326ac47e};
pinned \code{drat-trim} accepts all four.  Isolated checker walls are 112.12,
112.03, and 107.11 seconds, median 112.03.  The median proof-on solver plus
checker pipeline is 482.923 seconds; checker time is validation overhead, not
solver score.

Scratch is local NVMe XFS, while the repository is NFS over RDMA.  The staged
CNF, proof, and checker input remain local.  Proofless output is negligible.
Writing the 1.514-GB proof adds about one second of system time and negligible
I/O PSI.  Checking sees cached pages and reports no physical filesystem input.
Thus current solver timing is not I/O-bound.  Local staging remains mandatory;
putting proof or CNF traffic on NFS would create a different protocol.

\section{Approved policy and disposition}
The user-approved stable contract is:
\begin{enumerate}
\item Routine timing uses separate one-solver candidate/baseline jobs,
\code{-c 12}, an exact 48,000-MiB SLURM allocation, no whole-node exclusivity
or all-memory reservation, and the applicable 16-GiB solver process limit.  The allocation
matches six physical cores at the effective 8,000 MiB/core; it does not raise
the solver limit or reserve memory bandwidth.  The exact MiB spelling permits
16 jobs within configured node memory 769,024 MiB; \code{48G} would round up
and permit only 15.  Require each CPU mask to cover one complete L3
domain.  Launch both arms in the same wave as separate jobs; never serialize
them in one allocation.  \code{-c 4} remains valid for functional work, not
timing.
\item Bind each solver to one granted hardware thread and record occupancy
across all partitions.  Occupancy is a covariate and rejection diagnostic, not
a reason to reserve an otherwise idle 96-core node.
\item Require verified node-local scratch for CNF, proof, and checker work.
Record node, CPU mask, time, cycles/instructions/IPC/migrations, load/PSI,
proof identity, checker time, and cleanup.
\item For a performance claim that accepts or rejects a repair, require three
independent exact-state paired waves.  Each wave concurrently runs one separate
candidate job and one separate baseline job, crossing arm placement over
node/L3 positions when practical.  Report the median paired
candidate/baseline ratio and its full range, never best-of.  An absolute
headline is secondary and allowed only when both arms' complete ranges are at
most 2\%; otherwise it is environmentally invalid, not a solver regression.
This requirement does not repeat fuzzing: each fuzz checkpoint remains one
Claude-owned campaign.  Correctness gates and ordinary diagnostic probes keep
their existing predeclared contracts.
\item Keep proof-on solver time, proof-off diagnostic time, and checker time as
three separate quantities.  Never subtract unmatched shared-node runs to price
proof generation.
\item Never request \code{--exclusive=user --mem=0} or another whole-node
reservation for timing or diagnosis.  Use paired ratios, cross-partition
occupancy, perf service-rate evidence, and naturally observed load windows.
Full-width tier arrays retain their existing eligible-width/no-node-constraint
contract and use aggregate paired evidence.
\end{enumerate}

Allocation-only probe \code{1648628} verifies
\code{SLURM_CPUS_PER_TASK=12}, \code{SLURM_MEM_PER_NODE=48000}, and CPU mask
\code{0-5,96-101}, exactly one L3 domain.  Its wrapper exits nonzero only after
recording that evidence because this cgroup-v1 cluster lacks the optional
cgroup-v2 \code{memory.max} path; no solver ran.  Initial probe \code{1648627}
is infrastructure-invalid because its log was placed on compute-local scratch.
Neither probe is solver or fuzz evidence.

For the accepted pin, 367.045--372.354 internal seconds (median 368.307) is the
supported ordinary shared-node \code{-c 12} calibration.  Routine development
decisions use paired ratios.  A stable paired slowdown is real solver evidence
even if both arms exceed 400; an unstable absolute observation is not.
The technical report and campaign are complete, and the approved contract is
now reflected in the Development Plan.  Phase 4.25 broad search-quality
convergence resumes after the pending consolidation fuzz verdict and wrap-up.
