\section*{Executive outcome}
The earlier Vivify variable-range cutoff was indeed unsupported and remains
removed.  The next rank-27 divergence was not another Vivify heuristic.  The
two solvers had identical EVSIDS scores and retired the same 369 variables,
but Tactix removed those variables from its equal-score heap in environment
batch order.  Kissat's source delays deactivation until the single Substitute
call after Sweep and scans the complete union in compact internal-variable
order.  That order difference changed heap topology and selected a different
35th decision after Probe.

Tactix now preserves the same transaction.  Ordinary Substitute emits
retirements in permanent first-import order; Sweep normalizes only the suffix
it produced; DefaultPolicy extends that suffix through the mandated
post-Sweep Substitute so any additional SCC variables join the same scan.
Vivify's earlier retirement prefix stays ahead of it.  The repair contains no
formula range, instance identity, rank, hash, literal, deadline, or tuned
constant.

The repaired candidate matches all 369 retained Kissat heap removals exactly,
including scores and heap positions, and all 481 decisions through the next
conflict.  Release passes 72/72.  The full 28B+5C guard passes 66/66 with every
model and proof checked and zero residue.  Immutable rank 27 remains UNKNOWN
at 1,200.004 seconds; its partial proof was hashed and deleted, so rank 27
remains open without certificate residue.

\section*{Why this appeared to be Vivify}
The common state sits after two Vivify calls, TransitiveReduce, Sweep, and its
follow-up Substitute.  Vivify's terminal effects had already been audited:
all 69 binary-producing probe effects matched.  Nevertheless, the first
search decision difference appeared immediately after this combined Probe
pipeline, so a candidate-range or clause-order explanation initially looked
plausible.

A filtered heap trace separated formula effects from representation.  After
34 shared decisions, Kissat's heap root was external variable 230665 and
Tactix's was 230802, but both scores were exactly
\code{2.6056478753115483e+24}.  Thus score bumping was not the cause.  Both
traces then showed 369 retired variables with identical sets.  The first 26
heap removals were byte-for-byte equal; removal 27 was variable 95250 in
Kissat and 95251 in Tactix.  Equal-score binary heaps preserve this mutation
history, so different removal order is enough to change the root.

\section*{The source-backed lifecycle}
Kissat's \code{sweep.c} proves an equivalence, rewrites the retiring literal's
connected clauses, and records representatives in \code{sweeper->reprs}.  It
does not deactivate the variable.  The fixed Probe pipeline then calls
\code{kissat\_substitute};
its representative-removal pass walks
\code{for (all\_variables(idx))} and deactivates the entire SCC union.  Kissat's
compact internal indices correspond to Tactix's permanent first-import order.

Tactix must create a reconstruction witness as each inline environment
rewrites its variable-width arena.  That representation requirement does not
authorize the environment boundaries to become heuristic scheduling state.
The first repair attempt made this distinction clear: ordering each batch by
equivalence emission still began \code{95251, 420557, ...}, while Kissat began
\code{95250, 95251, 95252, ...}.  Ordering within each environment by import
rank then matched removals 1--363, but four Sweep variables still preceded two
SCC variables discovered only by the follow-up Substitute.  Carrying the
suffix boundary across that follow-up reproduces Kissat's one union.
