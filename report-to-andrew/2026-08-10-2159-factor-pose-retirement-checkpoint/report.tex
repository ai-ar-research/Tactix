\section*{Executive summary}

This checkpoint advances the open Phase-4 \code{mod4block} fixture in two
ways.  First, it closes two remaining Factor application-order details:
\tactix{} now applies a selected quotient chain from the last factor backward,
and emits each large quotient by preserving the chosen last row's clause pose
rather than the sorted remainder key.  The shipped-default event stream now
matches \kissat{} through conflict 346.  Conflict 347 is the already known
policy difference where \kissat{} performs first-round conflict reuse and the
shipped \tactix{} default does not.

Second, a matched-policy diagnostic with conflict reuse enabled moves the
causal frontier substantially later.  Decisions, conflicts, and backtracks
remain identical through conflict 1009.  Conflict 1010 is the first different
learned-clause/backjump outcome.  An earlier textual difference retains a
root-false literal \code{-89} in a \tactix{} clause, but does not alter the
decision/backtrack sequence until this later analysis.  The next controlled
increment is to trace the conflict-1007--1010 reasons back to that clause's
creation or simplification boundary.  Factor should be reopened only if equal
input state reveals a grid, reference, update, or emission mismatch.

The same production experiment exposed an independent correctness defect: a
long release run exhausted the VMTF queue.  Analyze could bump a retired
variable, and Substitute could rediscover a retired variable through stale
binary edges and deactivate it twice.  Both active-variable boundaries are
now explicit and adversarially tested.  A 120-second diagnostic ran without
queue corruption.

This is not yet a shipped-performance close.  The clean shipped-default pin
does not solve within 120 seconds.  Conflict reuse solves this one fixture,
but previous broad evidence found it globally neutral-to-negative with severe
fragile losses, so the default is unchanged.

\section{Implementation decisions}

\subsection{Factor quotient construction}

The selected Factor grid is an ordered multiset of clause occurrences, not a
set of sorted remainders.  Two implementation details are consequently
load-bearing:

\begin{enumerate}[leftmargin=*,itemsep=2pt]
  \item The selected factor chain is consumed in \kissat{}'s
  \code{q -> prev} order.  Divider additions, LRAT resolution groups, grid
  deletions, and candidate updates all follow that reverse order.
  \item A large quotient copies the selected last-factor clause's existing
  literal order and removes that factor.  The interned sorted remainder remains
  only an equality key.  This preserves the initial watched pair after sparse
  watch reconstruction.
\end{enumerate}

Focused tests cover reverse application, sparse-resume binary order, repeated
large occurrences, assigned remainders, and a deliberately non-sorted
last-row pose.  The Factor calculus and implementation ledger retain the rule
as one indivisible occurrence-preserving mechanism.

\subsection{Retired-variable lifecycle}

The release crash was localized using three progressively narrower Slurm
diagnostics.  Queue exhaustion first appeared after roughly 1.39 million
conflicts.  A reciprocal-link alarm then found variable 1295 disconnected
while it was still counted as active.  Two mechanisms could violate that
invariant:

\begin{itemize}[leftmargin=*,itemsep=2pt]
  \item the queue and score bump helpers counted a retired-variable bump but
  continued into the reconnect/update operation; and
  \item Substitute's SCC roots and edges treated every unassigned literal as
  active, so stale binaries mentioning an already substituted extension could
  produce a second retirement.
\end{itemize}

Both bump helpers now return immediately for a retired variable.  Substitute
requires an unassigned, non-retired variable for SCC roots, SCC edges, and its
LRAT binary-path traversal.  The tests directly bump a retired variable and
verify unchanged queue endpoints, links, heap score, and population; a second
fixture retains stale equivalence binaries around a retired variable and
requires no duplicate SCC or retirement event.

\section{Limitations and unresolved risks}

\begin{itemize}[leftmargin=*,itemsep=3pt]
  \item The shipped-default \code{mod4block} fixture remains open because it
  has neither a terminal solve nor a verified cumulative production gain.
  \item The exact creator or owner of the root-false \code{-89} clause payload
  is not yet classified.  Changing Factor without a common-input mismatch
  would risk fitting a downstream symptom.
  \item The 120-second queue diagnostic is strong reach evidence, not a proof
  that every retirement path is covered.  The broader N1 retired-Decide item
  in \code{PROGRESS.md} remains open.
  \item The scripted-default demo was not part of the clean aggregate local
  run because it is known to run slowly in this environment.  All 68 other
  registered tests passed.
\end{itemize}

\section{Next concrete actions}

\begin{enumerate}[leftmargin=*,itemsep=3pt]
  \item From job \code{1607094}, compare the conflict reasons and learned
  clauses at conflicts 1007--1010, then trace the first unequal source clause
  backward to its startup creation or simplification event.
  \item Reopen Factor only if the two solvers share the same input grid and
  differ in exact source reference, quotient emission, update order, or effort
  stop.  Otherwise repair and test the owning simplification/watch lifecycle.
  \item Re-run the shipped trace-off production gate, proof/model verification,
  and earlier P4A fixtures before accepting any change.  Require a cumulative
  production gain; do not enable global conflict reuse from this fixture alone.
  \item Once \code{mod4block} closes, return to \code{mp1} and implement
  \code{SP-VIVIFY-DEDUCE-1} only as the complete Vivify deduction terminal-state
  machine described in the implementation ledger.
\end{enumerate}
