\paragraph{Outcome.} A rejected online-program configuration no longer closes
the C input stream. All three public versions now convert and validate the
request, transactionally install it, and only then finalize input. The earlier
AM438 audit correctly found the side effect but treated the reorder as unsafe
without confirming the variable map: source inspection shows finalization
retires absent variables without remapping their literal identities. Accepted
requests still finalize before any online step runs. The public header states
the new boundary. No proof rule, default schedule, search behavior, or checker
contract changed. The detailed evidence is the AM442 technical report under
\texttt{benchmarks/reports/}.

\paragraph{Validation.} New C regressions cover v1, v2 and v3 in proofless,
early-LRAT and late-LRAT sessions. They test conversion and executor
rejections, nested-payload failures, an unfinished clause, later additions,
successful configuration, and the post-success input closure. Five focused
API/proof tests pass in both Debug and Release; the two affected ASan+UBSan
tests pass with leak detection. Six 10-byte LRAT refutations from the early
and late paths independently return \texttt{s VERIFIED UNSAT} under pinned
CakeLPR and the exact original test CNFs. A deliberately mismatched proof
returns no verified verdict, although this checker exits zero on failure.
The six retained proofs and two CNFs are in the AM442 technical evidence.

\paragraph{Limitations and next actions.} This is an API-lifecycle repair,
not a production online learner. Session-owned live DefaultPolicy stepping and
owned branching/reduction switches still require staged refactoring. Affected
fuzz has not accepted this snapshot. The old-pin full Debug job had passed
186/187 tests with its final scripted demo running, and both extended AES
checker tasks were still running; none tests this new snapshot. H2's canonical
no-option DSR rejection and the combined N1--N4/performance gates remain
open. Finish those gates and the final learning-readiness assessment before
launching the requested full Tier D comparison on hwulab.
