\section*{Executive summary}
Source-backed tracing localized a portable Vivify throughput gap to physical
arena reclamation after each tier band.  Kissat keeps shortened records in
place across the dose and reclaims once afterward; Tactix performed a
logical-order collection after every changed band.  The accepted repair keeps
one rule-owned reclamation transaction across the DefaultPolicy dose, rebuilds
the next band's watches in the same logical order when records are still in
place, and performs one collection at dose end.  Canonical public Vivify still
creates and drains its own transaction, preserving the complete N1 action
surface and the proof-rule/strategy boundary.

The exact source diff has SHA-256
\hashcode{a8cd5650a880948cafa928120bf7d0eb36cc103aa081626a2c9b07977ee35fdd};
the clean Release binary has SHA-256
\hashcode{4b3f7467b69e165686e271124d79a6b4ba977c2d6829a72afacf19ec23bc5e6a}.
An exact Rank-27 prefix preserves the 64-row event trace and lowers Vivify from
1.730 to 1.146 seconds.  Independent full Rank 27 improves wall time 433.41 to
427.29 seconds and Vivify 52.515 to 38.473 seconds.  The complete B28+C5 gate
passes 66/66 independently checked tasks at 0.968834x predecessor PAR-2 with
zero solve loss, invalidity, cleanup failure, or certificate residue.  Claude
Code's authoritative exact-source fuzz verdict is terminal PASS: 30,000
generated cases and 81 corpus replays produced no sanitizer, crash, invariant,
model, proof, or differential failure.

The Release suite is 73/74.  Every functional, proof/model, trace, boundary,
reset, cleanup, and hygiene test passes; only the already recorded opt-in
documentation-size policy debt fails.  This closes the isolated Vivify
increment.  It does not close convergence or make 300 seconds a stopping
criterion.

\section{Owner and implementation}
The accepted behavior before this increment already gave Vivify stable radix
ordering and exact candidate-order parity.  Traces of the remaining broad
throughput gap showed repeated reclamation between independently budgeted tier
bands.  Tactix's proof rule appends a packed replacement and historically
collected immediately to recover logical clause order.  Kissat's corresponding
dose retains shortened records until all bands have run.

The repair introduces \code{VivifyReclamationBatch}, whose only state records
whether retirement or inheritance requires later collection.  Every band runs
through the ordinary registry dispatch frame using \code{apply_rule_with}; the
alternate entry point changes no guard, timer, trace, journal, or proof-rule
framing.  If an earlier band changed records, the next band rebuilds large
watches from persistent logical source-position keys, reproducing the watch
stream that per-band logical-order collection would have produced.  The policy
then collects once after the dose unless the solver is inconsistent.  Direct
\code{vivify_apply} and \code{vivify_try} own and drain a local transaction, so
standalone rule semantics remain complete.

The change contains no benchmark name, identity, rank, time limit, per-instance
arm, or tuned constant.  It changes storage timing only after the exact
candidate/effect transaction has established the same logical order.  Proof
addition/deletion, reconstruction, scheduling budgets, candidate order, and
N1--N4 remain unchanged.

\section{Rejected consolidation investigations}
The isolated Substitute call-level deferred-reclamation prototype preserves a
short exact trace but adds 1,800 ticks and regresses full Rank-27 internal time
552.836 to 562.824 seconds while increasing memory.  It is rejected and fully
reverted.  Residual BVE is not presently a demonstrated common-state worse-side
owner: refreshed current Tactix spends 15.958 seconds versus current Kissat's
16.32 seconds, while their trajectories differ; the last exact BVE weakness,
antecedent admission, is already repaired.  No BVE source change is retained.

Residual Congruence remains a measured but unowned gap: the refreshed matched
prefix is about 1.830 seconds versus current Kissat's 1.644 seconds.  Three-
inline and two-inline closure layouts preserve exact prefix state but do not
improve full Rank 27; the latter regresses wall time 544.52 to 546.69 seconds
and raises observed RSS.  Both are rejected and fully reverted.  Generic key-
layout guesses are closed; any return must first localize exact closure
matching or maintenance work.

\section{Disposition and next work}
The terminal gate and fuzz PASS promote cross-band Vivify reclamation as a
portable common-state representation repair.  The next convergence increment
returns to broad search quality against the accepted current-Kissat comparator:
freeze this binary as the new Tactix baseline, identify the earliest exact
common-state point where equal cost yields weaker learning or pruning (or equal
logical work costs more), and trace decision, propagation, restart/reduce, and
inprocessing schedule order before changing behavior.  Residual Substitute
maintenance and the smaller Congruence closure gap remain documented owners
only when exact tracing demonstrates them.  Every future repair remains
isolated through exact prefix, full Rank 27 plus mechanism-relevant B+C, the
complete checked gate, Claude-owned fuzz, and a separate report/commit.
