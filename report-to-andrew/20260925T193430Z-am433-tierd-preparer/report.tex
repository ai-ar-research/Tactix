\section*{Outcome}
The future 1,166-instance Tier-D Tactix comparison now has a preparation
path for automatic certificates, complete frozen checker pins, anonymous
node-local scratch and the requested first-winner per-task limits. This is a
tooling checkpoint, \emph{not} a submitted or accepted Tier-D run. H2/N2,
the cumulative coverage and performance gates, N1/N3/N4, and the
online-learning refactors remain open. The detailed change and dry-run
record is \href{../../benchmarks/reports/2026-09-25-am433-tierd-automatic-preparer.md}{AM433}.

\section*{What changed and what was verified}
The older dedicated Tier-D launcher still forces \texttt{--drat}; that is a
compatibility mode, not the solver's default automatic proof behavior. The
anonymous-scratch preparer now selects explicit \texttt{--dsr} or
\texttt{--auto-proof}, pins the complete checker bundle against frozen
hashes, and budgets the full solve plus checker window. Automatic output is
content-routed by the existing runtime: startup PBP to VeriPB/CakePB,
witnessed DSR to no-option \texttt{dsr-trim}/Trestle, and witness-free DSR to
DRAT/CakeLPR, with original-CNF checking.

An unsubmitted full-union dry run generated 1,166 tasks, an unthrottled
\texttt{0-1165} array on \texttt{cpu-dense-hwulab-q}, four CPUs, 32 GiB,
5,000 solver seconds, 45,000 checker seconds, and a 14:15:00 scheduler
allowance. Its checker bundle passed the runtime pin contract. The first
dry run exposed a preparer-local source-path shadowing bug; after repair, a
second dry run verified the exact source-tree path and resource fields.
Both temporary campaigns were never submitted and were moved to recoverable
trash. Focused protocol tests, 17 runtime/scratch unit tests, Python
compilation and the memory-enforcement test pass. Compute-node validation
of a final accepted binary is still required before submission.
