This checkpoint restores the retained LymphoSAT-derived SAT constructors as
ordinary Tactix actions.  Every stable Lucky identity from 0 through 24 is
again enumerable and replayable.  The change is deliberately a SAT-recovery
step: it does not turn bounded constructor failure into UNSAT, and it does not

No benchmark, baseline, or portfolio experiment was launched.  The expected
owner recovery is based on previously checked saved evidence and restoration
of the same retained implementations.  Current target closure and performance
remain unmeasured until the authorized regression and owner-instance gates are
run.

\section*{Action and soundness boundary}

Lucky IDs 6--14, 17, 18, and 21 retain their historical SAT-constructor
meanings.  IDs 15/16 remain proof-producing st-connectivity and signed
cardinality actions; 19/20/22 remain startup proof actions; and 23/24 remain
the separate proof-only parity and exact-one actions.  In particular, IDs 6
and 7 no longer call the refutation engines.  An inconsistent parity or
exact-one structure therefore makes the SAT constructor decline, while the
explicit proof identity may return UNSAT only through its certified path.
The instance dispatcher also keeps SAT-only IDs ahead of the shared root
propagation drain.  Thus an unpropagated root contradiction cannot be
misattributed to a constructor; direct ID-6/7 controls verify that they return
no change without marking the kernel inconsistent.  Proof-capable identities
and the canonical probe cascade retain the root-closure path.

Every completed constructor assignment is checked against the whole live CNF
before Tactix returns SAT.  Parity, one-hot GF(3), affine, DirectCSP, Oddball,
and graph-labeling searches can publish a signed partial assignment when they
do not finish.  A zero entry remains unknown; it is not converted to a false
phase.  Partial candidates affect only the shared guidance channel and cannot
return SAT or UNSAT.  Focused tests add variables outside the recovered
structure and verify that they stay unknown in parity, one-hot, affine,
DirectCSP, Oddball, and graph-labeling publications.

DefaultPolicy restores the historically enabled 6/7/9, 11--14, 17, and 18
opportunities and retains the restored Oddball ID 10 opportunity.  Graph
labeling ID 21 remains opt-in because its production effort dose has not been
accepted.  Affine ID 8 is public and random-selectable, but no historical
DefaultPolicy stage existed, so this checkpoint does not invent one.

The random controller enumerates the entire finite Lucky catalog and binds
each typed reference profile to the selected stable identity.  The legacy
random-program generator also binds sampled parity, one-hot, affine, Fermat,
lookup, SIMON, st-connectivity, signed-cardinality, exact-cover,
independent-set, graph, and Ramsey parameter types only to compatible actions.
One-hot sampling selects either GF(3) ID 7 or DirectCSP ID 9.  Configuration
fingerprints, C configuration, C++ replay, feedback, and invalid cross-identity
rejection cover the restored typed paths.
