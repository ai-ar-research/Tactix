\section{Outcome}

Rank 5 exposed a genuine startup-lifetime memory excess rather than a search
or simplification defect.  The accepted solver allocated several per-variable
images for a 58,633,530-variable SAT formula even though early Lucky terminates
before preprocessing or search can consume them.  The promoted repair defers
the cold rule state and DefaultPolicy guidance until the first failed early
Lucky opportunity.

were independently checked against the original CNF and every run left zero
certificate and scratch residue.

\section{Portable lifecycle boundary}

The kernel can now defer 40 bytes per declared variable of BVE retry, touch
epochs, Backbone priority, analysis marks, and probing stamps.  The shipped
DefaultPolicy frontend additionally leaves roughly 35 bytes per variable of
VMTF, EVSIDS, phase guidance, and compact import-order storage unattached.
Startup propagation and early Lucky still advance the same event counters and
epochs while these images are absent.

If early Lucky returns unknown, a single explicit boundary reconstructs the
first-round cold-state predicates.  The existing \code{ScopedHeuristics} path
then consumes the parser-retained activation order before sparse collection
and every subsequent preprocessing or search rule.  Reader helpers assert
that the cold storage has materialized.  Random, replay, stress, bare-kernel,
and caller-supplied heuristic sessions retain their eager lifecycle.

This is an allocation-lifetime repair only.  It changes no proof rule,
calculus, rule admission, budgets, candidate order, logical transition,
scheduling state, or N1--N4 disposition.  It contains no benchmark identity,
rank, hash, deadline, per-instance branch, or tuned threshold.  Root values
created before heuristic attachment are fixed and therefore outside the later
decision surface.
